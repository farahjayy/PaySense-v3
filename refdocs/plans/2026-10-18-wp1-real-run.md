# Plan — WP1 Make the existing app really run

> Execution: `refdocs/execution/2026-10-18-wp1-real-run.md`. Scope: `refdocs/fintechathon-2026/work-packages.md` WP1.

## 1. Why this exists
v2 was built and tested on an in-memory database and a stub model. Before adding anything, the competition copy has to be shown working end to end on its own Supabase project with the served risk model, and the demo story has to be found by running the real model rather than assumed.

## 2. What's already covered
- `0001` and `0002` are applied to the v3 project; the 20 integration tests exist; `scripts/smoke_live.py`, `scripts/seed_users.py`, `ml/uat/shift_persona.py` and the three persona CSVs exist.
- The browser journey exists against the in-memory app with a stub model (`tests/e2e/journey.spec.ts`).

## 3. Scope
**In:** the integration tests on the real project; uvicorn on the real database; the smoke script; three persona accounts with unguessable usernames (kept only in `data/private/`) loaded through the real API; the demo scenarios found with the real model and written by script; a Playwright journey against the real model.
**Out:** deployment (WP11); new migrations (none needed); changing the model (WP16).

## 4. Approach
- `scripts/load_personas.py`: seed, shift, import through `POST /api/import/csv` + `/confirm`, confirm the detected recurring items (what a tester does on the Recurring screen), read the forecast. Idempotent (duplicates flagged by the preview).
- `scripts/find_demo_scenario.py`: a fixed grid from the demo story (work-packages §6) through `POST /api/risk/check` (stores nothing); writes `evidence/demo-scenario/scenarios.json` and `refdocs/fintechathon-2026/demo-scenario.md`. Waits out the per-user rate limit instead of failing.
- `playwright.real.config.ts` + `tests/e2e-real/`: the production build against the running real API; a throwaway account is created by `scripts/e2e_real_account.py` and deleted after (cascade).

## 5. Risks & unknowns
| Risk | Confidence | Mitigation |
|---|---|---|
| `check_rls.py` needs the anon key, which is not in this environment | Certain | Ask the author (questions.md); the no-key request is refused (401) |
| The real model may not give a Safe scenario for the demo story | Medium | Report what it gives; never pick numbers by hand |
| Playwright's pinned browser build differs from the container's | Certain here | `PW_CHROMIUM_PATH` launch option (environment only) |

## 6. Definition of done
- `pytest -m integration` passes on the v3 project; smoke passes against uvicorn on the real database.
- Three persona accounts exist, their forecasts unlock (`status: ok`).
- `demo-scenario.md` is generated by script from real responses.
- The real-model Playwright journey passes: login → import → forecast → check → confirm → saved report.
