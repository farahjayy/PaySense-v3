# Plan — P9 UAT kit

> Execution: `refdocs/execution/2026-10-09-p9-uat-kit.md`. Source of truth for scope: PRD §3 and §6 (P9).

## 1. Why this exists

The dissertation claims the system helps a student decide better about a BNPL purchase. That claim needs evidence from people other than the author: a handful of testers use the app on synthetic persona data, answer standard questionnaires, and make the same purchase decision before and after seeing the risk check. The kit makes a session repeatable and the analysis mechanical, so what is reported is what the testers said and nothing else.

## 2. What's already covered

- Three persona CSVs (`data/personas/`), generated by `ml/datagen` from the same cited parameters as everything else (D-08).
- `scripts/seed_users.py` and `app/seed.py` create a tester account on a persona (idempotent).
- The import path, dashboard, plans and (after P6/P7) the risk check are the thing being tested.
- UAT ethics/consent approval is not required: testers use synthetic persona data only (author, 2026-10-08, PRD §8).

## 3. Scope

**In**
- A participant information note (plain language, one page): what the session is, that the data is synthetic, that taking part is voluntary and can stop at any time, what is recorded (answers only, no names against answers), who to ask. It carries the PDPA-aligned privacy statement; it is **not** a consent form for personal financial data, because none is collected.
- A task script with an observer's sheet (what to say, what not to say, what to note).
- Instruments: the System Usability Scale (ten standard items), an explanation-clarity set (four items), and three pre/post decision vignettes with a confidence rating.
- A tester roster template and a batch seeding script that reads it.
- An analysis script: SUS score per tester, mean and 95% confidence interval; clarity item means; the decision-switch table per vignette (before → after, with the direction measured against a stated risk ordering of the options).
- A format example (clearly marked invented, for testing the script only) and a dry-run procedure.

**Out, with reasons**
- Running real sessions: needs the author and her testers. The kit is ready; the data is hers to collect.
- Significance tests on the switch counts: with 5–7 testers they would overstate; counts and directions are reported, and the analysis says so.
- Any storage of responses in the app or the database: responses live in CSV files under `uat/data/` (gitignored for real runs) and nowhere else.
- Free-text coding scheme: observers' notes are kept as notes.

## 4. Approach

- `uat/` at the repository root holds everything a facilitator touches (documents and blank response templates). The analysis code is `backend/ml/uat/` (offline; the API never imports it) and runs as `uv run python -m ml.uat.analyse`.
- The vignette options and their risk ordering live in `uat/vignettes.yaml`, so the analysis reads the ordering from the same file the facilitator reads the options from.
- SUS scoring is the published formula (odd items score − 1, even items 5 − score, sum × 2.5). The confidence interval is a t-interval on the tester scores; with n below 2 it says no interval can be computed.
- Responses are validated on load (range, completeness, known vignette, known option); a bad file is an error that names the row, never a silently smaller n.
- A spreadsheet export of results escapes leading `= + - @` (deferred from the P1–P4 reviews).

## 5. Risks & unknowns

| Risk | Confidence | Mitigation |
|---|---|---|
| The risk check is not available until P6/P7 are done, so the task script describes it as it will be | High that wording needs a re-read once built | The execution doc has a "re-read against the finished app" step before anything is given to testers |
| Five to seven testers give wide intervals | Certain | Report the interval, state n, and do not claim more than a descriptive result |
| Vignette options being ordered by risk is a judgement | Medium | The ordering is written down in one file with the reason; the analysis reports the ordering used |
| Participants sharing a screen with a facilitator may be nudged | Medium | The facilitator script says what not to say; sessions note anything said |

## 6. Definition of done

- `uat/` contains the information note, task script, instruments, vignettes, roster template and blank response templates.
- `uv run python -m ml.uat.analyse --data uat/data/example` prints SUS mean and 95% CI and the decision-switch table, and the example is marked as invented in the output.
- Tests cover SUS scoring against hand-computed cases, the interval, validation errors, and the switch table including direction.
- `scripts/seed_testers.py` parses the roster (tested without a database).
- STATUS, CHANGELOG updated; nothing here states a date or deadline.
