# Plan — WP19 Privacy and responsible use

> Execution: `refdocs/execution/2026-10-18-wp19-privacy.md`. Scope: work-packages.md WP19.

## 1. Why this exists
Security and compliance is 30% of the score, and Malaysia's PDPA gives people the right to see and correct what is held about them. The app now also sends derived figures to a third-party model provider (D-47, D-53), which people must be told about before it happens.

## 2. What's already covered
User scoping on every table; RLS with no anon access; the audit log; data minimisation for the model (derived figures, bounded transaction lists, redactable descriptions).

## 3. Scope
**In:**
- **Consent:** a versioned notice (what is stored, what the assistant sends to the model provider, where data lives, that nothing is financial advice or a credit decision, that every write is confirmed by the person) shown on first login; acceptance stored per user (`user_settings.consent_version`, `consent_at`; migration `0006_privacy.sql`). `GET /api/account/consent`, `POST /api/account/consent`. The assistant's chat refuses to call the model until the current notice is accepted (guided mode still works).
- **Export my data:** `POST /api/account/export` → JSON of every row the user owns in every table (no passphrase hash, no token version).
- **Delete my data:** `POST /api/account/delete` with the typed phrase `delete my data` **and** the passphrase (the two confirmations); removes every row the user owns in every table, resets settings and onboarding, keeps the account so the person can start again; a test asserts per table that the user's rows are gone and another user's are untouched.
- Responsible-use statement on the login page and the assistant panel (frontend, WP5/WP7) and in docs; a PDPA and data-minimisation note in `SECURITY.md` (WP8).
**Out:** deleting the account itself (seeded accounts are managed by the author); data-retention schedules (the author's policy).

## 4. Approach
`ScopedTable.delete_all(user_id)` — scoped by construction — over an explicit list of every user-owned table, children before parents (transactions, events, actions, budgets, categories, limits, locks, plans → instalments by cascade, risk checks, recurring items). The list is checked by a test against the fake's known tables, so a new table cannot be forgotten.

## 5. Risks & unknowns
| Risk | Confidence | Mitigation |
|---|---|---|
| A new table added later is not deleted | Medium | Test fails when a user-owned table is missing from the list |
| A partial delete after a database error | Low | Each table is deleted in one request; a retry finishes the job (idempotent) |

## 6. Definition of done
Delete removes every user-owned row in every table (asserted per table) and nothing of another user's; export holds every table; consent is required before the model is called; two-user and unauthenticated tests.
