# Plan — WP8 Security self-assessment and scans

> Execution: `refdocs/execution/2026-10-18-wp8-security-self-assessment.md`. Scope: work-packages.md WP8.

## 1. Why this exists
Security is 30% of the judging. Judges need one document that names the assets, the actors and the abuse cases, maps each to a control that exists in code with a test behind it, and lists what is *not* closed. Scans give independent evidence that the dependency tree and the git history are clean, or say exactly where they are not.

## 2. What's already covered
Every control the document describes already exists and is tested: WP18 (passphrase, revocation, quotas, admission cap, locks, ledger cap), WP4a–WP4d (tiers, policy, pending actions, number check, audit log, untrusted data blocks), WP19 (consent, export, delete), and the v2 controls (scoping, RLS, CSP, body limits, artefact hash check, fail-fast secrets).

## 3. Scope
**In:**
- `SECURITY.md` at the repo root: architecture, the three tiers, a controls table (each row names its code and its test), threat model (assets, actors, abuse cases including prompt injection and confirm replay), known-risk list, scans, responsible use.
- `backend/scripts/run_security_scans.py`: pip-audit (runtime, and runtime + dev + ml), npm audit (production, and all), gitleaks over the whole history (redacted). Raw JSON and a generated `SUMMARY.md` in `evidence/scans/`. A scanner that cannot run is written as "not run", never as clean.
- An independent read-only security review of the competition diff by a review agent; confirmed findings are fixed with a test, the rest recorded in the known-risk list.
**Out:** a third-party penetration test; DAST against the deployed site (no deployment from this session).

## 4. Approach
pip-audit audits the exported pinned requirements as written (`--no-deps --disable-pip`), because the CPU torch wheel is not on PyPI and an install-based audit fails on it. npm audit is run twice so dev-only findings are visible and separable from what ships.

## 5. Risks & unknowns
| Risk | Confidence | Mitigation |
|---|---|---|
| Advisory databases change after the run | Certain | Command and generated summary kept; re-run before submission |
| A dev-only npm finding is read as shipped | Medium | Production and all-dependency audits reported separately |

## 6. Definition of done
`SECURITY.md` complete; `evidence/scans/SUMMARY.md` generated by the script from a real run; review-agent findings fixed or listed as known risks.
