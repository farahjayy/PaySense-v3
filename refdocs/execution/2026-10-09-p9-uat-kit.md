# Execution — P9 UAT kit

> Plan: `refdocs/plans/2026-10-09-p9-uat-kit.md`. Tasks run top to bottom. Each task carries its own **Verify** step; a task is not done until its Verify actually passes.
> If reality diverges from this doc, **edit this doc** (CLAUDE.md rule 4).

## Before starting

- Read `CLAUDE.md`, `refdocs/STATUS.md`, PRD §3 and §6 (P9), §8 (ethics note), ADR D-08, D-14, D-24.
- The kit never contains real personal data. Real response files go in `uat/data/<run>/` which is gitignored; only `uat/data/example/` is committed and it is marked invented.

---

### Task U1 — Analysis module (tests first)
- **Files:** `backend/ml/uat/__init__.py`, `load.py`, `sus.py`, `switches.py`, `analyse.py`; `backend/tests/ml/uat/`.
- **Steps:** SUS per tester and mean ± 95% t-interval; clarity item means; vignette loader that reads `uat/vignettes.yaml` (options, risk rank); switch table (pre → post counts, switched share, direction: safer / same / riskier by rank); confidence change; Markdown report writer; formula-injection escaping for any CSV the module writes.
- **Verify:** hand-computed SUS cases (all 5s on odd and 1s on even = 100; all 3s = 50), interval against a computed value, validation errors name the row, switch directions on a constructed set.

### Task U2 — Roster and seeding
- **Files:** `uat/testers.template.csv`, `backend/scripts/seed_testers.py`, `backend/ml/uat/roster.py` (parse and validate only), tests.
- **Steps:** roster columns `participant,username,display,persona`; usernames follow the existing username rules; personas must be one of the three; duplicates rejected; the script seeds each row through the existing `seed_user` and prints one line per tester. Persona CSVs are imported by the tester during the session (the import path is part of the task).
- **Verify:** roster parser tests; the script's `--dry-run` lists what it would do without touching a database.

### Task U3 — Documents and instruments
- **Files:** `uat/README.md`, `participant-information.md`, `task-script.md`, `instruments.md`, `vignettes.yaml`, `templates/{sus,clarity,vignettes}.csv`.
- **Steps:** write each in plain language; no dates, deadlines or schedule; terminology "financial health forecast" / "BNPL risk check".
- **Verify:** a test loads `vignettes.yaml` and checks every vignette has at least four options with distinct ranks and a stated reason for the ordering; a test checks the templates' headers match what the loader expects.

### Task U4 — Example data and dry run
- **Files:** `uat/data/example/*.csv` (invented, six testers, marked in each file's first line and in the report banner), `reports/uat/example.md` (generated).
- **Verify:** `cd backend && uv run python -m ml.uat.analyse --data ../uat/data/example --out ../reports/uat/example.md` runs and the report begins with the invented-data banner. The dry run with one real tester is for the author; the kit's README says how to run it.

### Task U5 — Re-read against the finished app
- **Steps:** once P6/P7 are green, re-read `task-script.md` against the real screens and fix any wording that no longer matches. Record the result in the changelog.

### Task U7 — Persona dates
- **Files:** `backend/ml/uat/shift_persona.py`, tests, `uat/README.md` ("Persona dates").
- **Why (found while writing the browser tests):** the persona CSVs end in December 2025, so on any later session date the imported ledger is stale. Shifting by whole weeks keeps weekday patterns and gaps.
- **Verify:** tests for the shift arithmetic and for the three real personas; once the personas are regenerated (see U8) a test that each shifted persona unlocks the forecast through the real engine.

### Task U8 — Personas must unlock the forecast
- **Finding:** `frequent_bnpl.csv` starts on a Tuesday (2 Sep 2025), so it has 16 complete Monday-Sunday weeks, one short of the 17 the forecast needs; the dashboard stays locked after import. The other two start on a Monday and have exactly 17.
- **Steps:** regenerate the three personas with at least 20 complete weeks (margin for shifting), starting on a Monday; add a test that imports each into the real forecast service and expects `status == "ok"`.
- **Blocked on:** the P5 label regeneration, which changes `ml/datagen`; do it after that lands.
