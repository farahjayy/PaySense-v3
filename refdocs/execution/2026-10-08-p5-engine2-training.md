# Execution — P5 Engine 2 training

> Plan: `refdocs/plans/2026-10-08-p5-engine2-training.md`. Tasks run top to bottom. Each task carries its own **Verify** step; a task is not done until its Verify actually passes.
> If reality diverges from this doc, **edit this doc** (CLAUDE.md rule 4).

## Before starting

- Read `CLAUDE.md`, `.claude/memory/preflight.md`, `refdocs/STATUS.md`, PRD §3.1 (Engine 2), §3.2 (feature table), ADRs D-05, D-07, D-09, D-11, D-14, D-28, D-31, D-33, `reports/engine1/README.md` (which model is served), `reports/datagen/README.md`, and the P4 audit notes in the CHANGELOG.
- `features.py` lives at `backend/app/engines/risk/features.py` and nowhere else. `ml/` imports it. The server refuses to start on a feature-hash mismatch.
- **Pre-registered before any training** (so they cannot be tuned afterwards): bands Safe < 0.10, Caution < 0.30, At Risk ≥ 0.30; primary metric Brier score against the soft label; the winner is the lowest mean Brier under the grouped 5×5 CV unless a simpler candidate is within one standard error and not significantly worse (Nadeau–Bengio, Holm-adjusted), in which case the simpler one is served and that is reported; calibration is whichever of none / Platt / isotonic has the lowest nested-CV Brier.
- Algorithms are fixed (D-05): Random Forest, XGBoost, LightGBM (monotone-constrained) and a logistic-regression benchmark. SHAP is P6.
- Never use `truth` from a profile as an input (D-31); never use the generator's recurring ground truth as confirmed items.

### Task D1 — `features.py` and the feature contract
- **Files:** `app/engines/risk/__init__.py`, `app/engines/risk/features.py`, `tests/engines/test_features.py`.
- **Steps:** one function `compute_features(inputs) -> Features` for the 16 features in PRD §3.2 (`disc_weekly_p50`, `disc_weekly_p90`, `disc_volatility`, `margin_monthly_p50_without`, `margin_cum_p10_without`, `income_p10_monthly`, `instalment_amount`, `num_instalments`, `monthly_fee_rate`, `instalment_to_income`, `dsr_with_purchase`, `active_plans_with_purchase`, `bnpl_outstanding_to_income`, `upfront_to_income`, `limit_utilisation_with_purchase`, `limit_known`), an ordered `FEATURE_NAMES`, `MONOTONE_DIRECTIONS`, and `FEATURE_SCHEMA_HASH` (a hash of names, order and definitions' version string). Inputs are plain data (ledger summary, plans, limits, proposed plan, Engine 1 `Simulation` pieces). Money in sen inside, ringgit-scaled only where the table says RM. Age, employment and persona are not accepted.
- **Verify:** `uv run pytest tests/engines/test_features.py` — hand-computed values for every feature, including a limit-capped purchase (D-28), `limit_known = 0`, no income (ratios guarded, not infinite), and a test that the hash changes when a name or order changes and that a forbidden-feature list (age, employment, persona, repayment history) is not present.

### Task D2 — Engine 1 summary for a horizon
- **Files:** `app/engines/forecasting/summary.py`, tests.
- **Steps:** from a `Simulation` pair (without / with the proposed plan) and the variable-series forecast, produce the Engine 1 numbers the features need (weekly discretionary P50 / P90 over the horizon, residual volatility, monthly margin P50 without, lowest P10 cumulative margin without, P10 monthly income). One function used by training and serving.
- **Verify:** hand-built simulations give the exact expected summaries.

### Task D3 — Label pipeline
- **Files:** `ml/engine2_train/__init__.py`, `ml/engine2_train/labels.py`, `tests/ml/engine2/test_labels.py`.
- **Steps:** for each profile index (generated on the fly by `generate_dated_profile`, with its own as-of day; `data/synthetic/profiles.jsonl` is not read): ledger as of `as_of`; recurring items = `detect()` over that ledger, all suggestions confirmed; plans with paid status on `as_of`; provider limits as *recorded*; `simulate` without and with the proposed plan, to the plan's last instalment (D-36); write `{index, label, p_without, label_monthly, p_without_monthly, horizon_capped, as_of, features, truth}` to `data/engine2/labels.jsonl` (gitignored) with `MANIFEST.json` (committed: label version, parameter hash, feature hash, file sha256, library versions, git commit). Deterministic seeds per profile; `--resume` continues an interrupted run of the same settings.
- **Verify:** `uv run pytest tests/ml/engine2/test_labels.py` — the label equals a direct `simulate` call on a hand-checked profile; reading `truth` raises in a test double; confirmed items come from detection, not ground truth; the plan status uses `as_of`.

### Task D4 — Dry run and label distribution
- **Steps:** label 1,000 profiles; record seconds per profile and the label histogram by persona and purchase ratio. If more than ~85% of labels fall below 0.02 or above 0.98, stop and record why before the full run. The label histogram by persona and purchase ratio, and the distribution of the baseline (`p_without`), are generated by `report.py`.
- **Verify:** numbers in the changelog; the histogram figure is generated by script.

### Task D5 — Full label run
- **Steps:** `uv run python -m ml.engine2_train.labels --profiles 10000` (streamed, resumable with `--resume`). The stress variants (a stale ledger, a missing month, income down 20%, the next PTPTN disbursement not arriving) are computed from the lockbox profiles by `stress.py` and kept apart: they are never trained on.
- **Verify:** manifest matches; counts; peak memory recorded.

### Task D6 — Training harness
- **Files:** `ml/engine2_train/train.py`, `cv.py`, `tests/ml/engine2/test_train.py`.
- **Steps:** duplicate-and-weight soft labels; the logistic benchmark first, then RF / XGBoost / LightGBM with `MONOTONE_DIRECTIONS`; Optuna inner loop (budget recorded); grouped, stratified 5×5 repeated CV on the development profiles (every tenth profile is the lockbox, D-37); metrics (Brier, log-loss, ROC-AUC at 0.30, calibration slope, ECE); Nadeau–Bengio tests. Leakage test: no profile appears on both sides of a split; a model given the label as a feature scores perfectly (so the harness would notice).
- **Verify:** `uv run pytest tests/ml/engine2/`; a small-config run end to end.

### Task D7 — Calibration, ablation, stress tests
- **Steps:** calibration chosen and fitted on single-repeat out-of-fold predictions of the development set and stored; the final model scored once on the lockbox (with the logistic benchmark and the constant); ablation (both arms tuned inside every fold, ΔBrier with a t-based CI, overall and for the baseline-under-0.10 subgroup); stress tests on the lockbox (income −20%, the next PTPTN disbursement not arriving, a stale ledger, a missing month, and an identity control with the same paths and seed); sensitivity runs (unconstrained model, learning curve, per-month shortfall definition).
- **Verify:** tables written by script.

### Task D8 — Artefact, start-up check, report, ADR
- **Files:** `backend/models/engine2/<version>/`, `app/engines/risk/artefact.py`, `tests/engines/test_artefact.py`, `ml/engine2_train/report.py`, `reports/engine2/`.
- **Steps:** export the winner + calibrator and `metadata.json`; a loader that refuses a mismatched `FEATURE_SCHEMA_HASH` (tested); generate the report (benchmark in every table, unflattering results included, limitations section stating that Engine 2 distils Engine 1); ADR for the winner and calibration; PRD §7 one-liner.
- **Verify:** `uv run python -m ml.engine2_train.report` regenerates `reports/engine2/` with an empty `git diff` on a second run.

### Task D9 — Audit
- **Steps:** `ml-auditor` on labels, features and training (leakage, parity with serving, honesty); `python-reviewer`; fix or list.

## What actually happened (2026-10-09 audit)

The ml-auditor reviewed the pipeline before the full training run. The nested grouped CV core held; the following were changed before any full run, and the labels were regenerated (label version 2):

- **D-36:** the 52-week simulation cap truncated 3,834 of 10,000 labels; a risk check now simulates to the plan's last instalment (`RISK_CHECK_MAX_WEEKS = 180`, dashboard unchanged).
- **As-of day per profile** (D-31 note): all labels had shared 2025-12-28, so the PTPTN position, semester and horizon were identical.
- **Feature schema hash** now covers the window constants (`RECENT_MONTHS`, `COMMITMENT_MONTHS`, ...), which moved into `features.py`.
- **D-37:** lockbox, both ablation arms tuned inside every fold (the full arm is the winner's own nested CV, reused), t critical value for the CI, calibration fitted on single-repeat out-of-fold predictions and stored, stress on the lockbox with an identity control and the calibrated model. The PTPTN stress variant now removes the next detected semester income (the original removed ledger rows dated after as-of minus 45 days, which changed nothing because PTPTN lands in March and September).
- **Report:** the baseline distribution, the share of profiles where the purchase moves the band, Brier overall and for the baseline-under-0.10 subgroup, label histograms by persona and purchase ratio, the Monte Carlo noise floor, versions and commit, and an explicit "Not done" list (the bias-term sensitivity). The hard-coded allowance sentence is gone.
- **Doc conflict resolved:** the plan said stale and incomplete ledgers join the training set; this doc said they are kept apart. They are kept apart (D-37 item 6).
- **Resumable:** the plan claimed it; `--resume` now makes it true.
