# Execution — P7 Frontend

> Plan: `refdocs/plans/2026-10-09-p7-frontend.md`. Tasks run top to bottom. Each task carries its own **Verify** step; a task is not done until its Verify actually passes.
> If reality diverges from this doc, **edit this doc** (CLAUDE.md rule 4).

## Before starting

- Read `CLAUDE.md`, `.claude/memory/preflight.md`, `refdocs/STATUS.md`, PRD §3, §4 and §6 (P7), `frontend/AGENTS.md`, and the relevant guides in `frontend/node_modules/next/dist/docs/` before using any Next.js API (this is Next 16; do not rely on memory).
- Rules that apply: web design quality (a specific style direction, not a template), web performance (app page JS under 300 kB gzipped, explicit image sizes, compositor-friendly motion), web security (no `dangerouslySetInnerHTML`, CSP already in `next.config.ts`), accessibility.
- The frontend never computes a score, forecast or provider rule, never talks to Supabase, and has no secrets. Types come from `lib/api/schema.d.ts` only.

---

### Task F1 — Foundations: data layer, formatters, component kit
- **Files:** `lib/api/queries.ts` (typed query/mutation hooks), `lib/format.ts` (dates, percentages, bands), `components/ui/*` (StatTile, BandBadge, ScoreRing, Banner, EmptyState, ErrorState, LockedState, Skeleton, Table, Dialog, Tabs, MoneyInput, DateInput, Segmented), tests for each.
- **Verify:** `npm run test`, `npx tsc --noEmit`, `npm run lint`; the money input round-trips with `lib/money.ts` for the same cases as the Python tests.

### Task F2 — Shell, routes, titles, skip link
- **Files:** `components/layout/AppShell.tsx`, `lib/nav.ts`, route stubs under `app/(app)/`, metadata per route.
- **Steps:** all routes in the navigation (Dashboard, Transactions, Recurring, Plans, Risk check, Import, Model card), a skip-to-content link, a unique page title per route, focus moved to the page heading on route change.
- **Verify:** tests for nav active state, titles and the skip link; keyboard walk in a test.

### Task F3 — Import
- **Files:** `app/(app)/import/`, components, tests.
- **Steps:** drop zone and file picker, upload to `POST /api/imports/preview`, preview table (mobile: cards) with per-row category/type edits and skip reasons, duplicate flags with a clear default, confirm via `POST /api/imports/confirm`, success state that leads to the dashboard. Error states for oversized, unreadable and empty files.
- **Verify:** component tests with mocked responses for each state; the persona CSV round trip in Playwright (F10).

### Task F4 — Dashboard
- **Files:** `app/(app)/page.tsx`, `components/forecast/*` (MarginFan, MonthlyMargins, WarningList, BillsDue), tests.
- **Steps:** locked state with progress toward four months and the reason; the health score and band with one sentence; the cumulative-margin fan with the zero line and the worst month; monthly margins; warnings beside the number (stale ledger, suspect months, unmatched confirmed items, `fallback`/`plain` bootstrap, capped horizon); bills due soon. Chart has a table alternative.
- **Verify:** tests for locked / stale / warning / ok states; axe; the text alternative equals the chart data.

### Task F5 — Transactions and recurring
- **Files:** `app/(app)/transactions/`, `app/(app)/recurring/`, tests.
- **Steps:** filtered list with month summary, add / edit / delete in a dialog, refunds and transfers shown for what they are; recurring: suggestions with one-tap confirm (sends `origin: detected` and the suggestion's `name` as `match_text`), manual add / edit / pause, the unmatched-item hint.
- **Verify:** tests per interaction and per error (409 `managed_by_plan` on plan-linked payments shows its explanation).

### Task F6 — Plans
- **Files:** `app/(app)/plans/`, `components/plans/*`, tests.
- **Steps:** list with status, create flow using `POST /api/plans/preview` live (limit split and checkout payment shown before saving), detail with mark-paid and bulk pay, bills by month, provider limits settings. The "Other provider" manual path.
- **Verify:** tests including the author's example (limit RM200, price RM300 → RM100 at checkout).

### Task F7 — Risk checker and reports
- **Files:** `app/(app)/risk/`, `app/(app)/risk/[id]/`, `components/risk/*`, tests.
- **Steps:** the form (provider, price, instalments, first payment date, optional manual total), the result (score ring and band with text and icon, the reasons, the smallest change that reaches Safe or the honest "no single change gets there", the with-and-without chart, the repayment flag kept visibly separate from the probability, data-quality notes), confirm → plan, and the frozen report page read back by id.
- **Verify:** component tests for every band and for "nothing stands out" / "no change reaches Safe"; the frozen page renders without the live ledger.

### Task F8 — Model card and onboarding states
- **Files:** `app/(app)/model/`, copy reviewed for terminology.
- **Steps:** what the forecast and the risk check are, what they were built from (synthetic students, cited and assumed parameters), how to read the bands, the known limits (narrow bands on short histories, savings not credited), versions from the API.
- **Verify:** test that no user-facing text contains "Engine 1" or "Engine 2".

### Task F9 — Accessibility and responsive pass
- **Steps:** axe on every screen in tests; keyboard-only walk of the main journey; reduced motion; contrast tokens re-checked; layouts at 375 / 768 / 1440 (cards instead of tables on phones).
- **Verify:** `npm run test`; screenshots generated by `npm run shots` at the three widths.

### Task F10 — End-to-end journeys
- **Files:** `tests/e2e/journey.spec.ts`, extensions to `backend/tests/e2e_server.py` if a seeded persona is needed.
- **Steps:** log in → import a persona CSV → dashboard shows a forecast → risk check → confirm → the plan appears; the designed cases through the UI; desktop Chrome and a Pixel 7 profile.
- **Verify:** `npx playwright test` green on both profiles.

### Task F11 — Reviews
- **Steps:** `react-reviewer`, `typescript-reviewer`, `a11y-architect`; fix or list. Bundle size recorded.
